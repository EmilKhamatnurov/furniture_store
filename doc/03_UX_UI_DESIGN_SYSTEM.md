# KHAMATNUROV MEBEL — UX/UI концепция и дизайн-система

Версия 1.0 • 17 сентября 2026

## 1. Концепция

Рабочее название направления: **Dark Atelier / Quiet Craft**.

Задача дизайна — объединить эмоциональность авторского мебельного бренда с удобством ecommerce. Премиальность строится не через золото, декоративный «luxury», сложные анимации или маленький контрастный текст, а через качество фото, ритм, типографику, материал, пустое пространство и точность интерфейса.

Ключевой принцип: **брендовые разделы могут быть темными и атмосферными; торговые разделы должны оставаться светлыми, понятными и быстрыми.**

---

## 2. Визуальные ассоциации

Сайт должен восприниматься как сочетание:

- каталога предметного дизайна;
- интерьерного журнала;
- мастерской/ателье;
- современного premium DTC ecommerce.

Не должен восприниматься как:

- магазин массовой корпусной мебели;
- маркетплейс;
- «дорогой» шаблон с золотыми кнопками;
- мебельный салон с десятками баннеров/скидок;
- portfolio-only сайт, на котором непонятно как купить.

## 3. Базовые токены

### 3.1. Цвета

Предварительная палитра (финальная проверяется на реальных фото):

```text
Ink          #11110F   — глубокий темный фон
Graphite     #1A1916   — вторичный темный
Milk         #F3F0E9   — основной светлый фон
Warm Paper   #EAE6DE   — карточки/альтернативный фон
Text         #191816   — основной текст
Muted        #77736C   — вторичный текст
Oak          #926B49   — теплый акцент от материала
Bronze       #A37F5E   — очень ограниченный интерфейсный акцент
Line Dark    rgba(25,24,22,.14)
Line Light   rgba(255,255,255,.16)
Error        системный, спокойный, WCAG-контрастный
Success      системный, без «кислотного» зеленого
```

Bronze/Oak не использовать как заливку каждой CTA. Главная CTA может быть Ink на светлом фоне или Milk на темном.

### 3.2. Типографика

Направление:

- display/brand: Prata или другой кириллический high-contrast serif после проверки лицензии и Web Vitals;
- UI/text: Manrope или близкий качественный grotesk.

Если performance/лицензия делает serif проблемой, допускается единая хорошо подобранная grotesk-система. Нельзя зависеть от внешнего Google Fonts CDN в production без отдельной оценки; предпочтительно self-hosted `next/font`.

Пример шкалы desktop:

```text
Display XL  72–96 / 0.95
Display L   56–72 / 1.0
H1          48–64 / 1.05
H2          36–48 / 1.1
H3          26–32 / 1.2
Body L      18–20 / 1.55
Body        15–17 / 1.55
Small       13–14 / 1.45
Label       12–13 uppercase/letter-spacing умеренно
```

На mobile использовать fluid `clamp()`, не просто уменьшать desktop на фиксированный процент.

### 3.3. Сетка

Desktop:

- max content width: 1440 px;
- обычный content container 1280–1360;
- 12 columns;
- outer padding 32–64;
- большие editorial секции могут быть full-bleed.

Mobile:

- 4 columns;
- padding 16–20;
- touch target минимум около 44×44 CSS px;
- safe-area для sticky bottom CTA.

### 3.4. Spacing

8px base scale, но premium layout требует крупных интервалов:

```text
4, 8, 12, 16, 24, 32, 48, 64, 80, 96, 128, 160
```

## 5. Header

### Desktop

Состояние top-of-page на темном hero:

- прозрачный/полупрозрачный;
- светлый логотип/текст;
- при scroll — компактный Milk/Ink header либо темный solid в зависимости от страницы.

Состав:

- logo;
- Каталог;
- Материалы;
- Для дизайнеров;
- О бренде;
- Доставка и оплата;
- search icon;
- account;
- cart с количеством.

Не перегружать верхнее меню блогом/гарантией/всеми служебными страницами — они доступны через вторичный menu/footer.

### Mobile

- логотип;
- menu;
- cart;
- account/search внутри menu или компактно в header;
- меню открывается как отдельный слой с крупными категориями, а не tiny dropdown.

## 6. Главная страница — целевой сценарий

### 6.1. Hero

Цель: за 3–5 секунд объяснить бренд и дать вход в коллекцию.

Контент:

```text
KHAMATNUROV MEBEL
Предметная мебель собственного дизайна
Собственное производство в Уфе. Серийная коллекция и индивидуальные решения. Доставка по России.
[Смотреть коллекцию] [Для дизайнеров]
```

Формулировка «из натурального дерева» не используется как общий umbrella-тезис, пока в стандартной коллекции есть МДФ в эмали и шпон.

Фон: реальная hero-фотография изделия/интерьера. Не использовать 3D-рендер как единственный источник доверия, если можно показать производство и реальные изделия.

### 6.2. Категории коллекции

Крупная editorial grid, не пять одинаковых карточек.

Пример:

- Столы — доминирующая карточка;
- Тумбы;
- Комоды;
- Столики;
- Стеллажи.

Каждая карточка ведет на реальную category URL.

### 6.3. Featured model

Одна флагманская модель с ценой «от», 1–2 отличительными деталями и CTA в карточку. Нужна для коммерческой ясности — пользователь должен быстро понять, что сайт продает конкретные товары онлайн.

### 6.4. Философия конструкции

Не иконки «Качество / Надежность / Сервис», а реальные визуальные детали:

- соединение 45°;
- подбор рисунка шпона;
- скрытый крепеж;
- фактура массива;
- финишное покрытие.

### 6.5. Материалы

Крупные macro-фото + ссылка в `Материалы и отделка`.

### 6.6. Как заказать

6 простых этапов. Не превращать в длинное «как мы работаем».

### 6.7. Для дизайнеров

Контрастный блок с кейсом/фрагментом чертежа/готового проекта:

- индивидуальные размеры;
- производство по проекту;
- нестандартные материалы;
- расчет;
- [Отправить проект].

### 6.8. Три поколения

Эмоциональная история ближе к концу страницы. Максимум 1–2 абзаца + реальное фото мастерской/основателя/рук в процессе. Полная история — на `/about/`.

### 6.9. Journal/Blog

3 полезных материала, связанные с товарами. Не выводить блог как новостную ленту предприятия.

### 6.10. Final CTA + Footer

CTA: выбрать модель или обсудить индивидуальный проект.

## 7. Категория

### Above the fold

- breadcrumbs;
- H1;
- короткий полезный intro 1–3 предложения;
- число моделей;
- sorting;
- filter button mobile / filters desktop.

### Product grid

Desktop 3 columns как базовый премиальный режим, допускается 4 на широких экранах при качественных фото.

Карточка:

- aspect ratio единый;
- hover secondary image на desktop, если есть;
- название;
- категория/материал — только если полезно;
- «от … ₽»;
- короткие swatches только при наличии реальных фото/значений;
- made-to-order label можно дать нейтрально: «Изготавливается под заказ».

Не показывать:

- псевдо-скидки;
- звездочки без отзывов;
- яркие badges «ХИТ» на каждом товаре;
- фейковый остаток «осталось 2».

### Filters

Desktop — side panel или top drawer в зависимости от ассортимента. Mobile — full-screen bottom sheet/drawer.

Фильтр должен:

- показывать число активных фильтров;
- иметь Clear all;
- не сбрасывать scroll странным образом;
- обновлять URL предсказуемо;
- не создавать indexable SEO-chaos.

## 8. Карточка товара

### 8.1. Desktop layout

Левая часть 58–65% — gallery. Правая 35–42% — sticky purchase panel.

В purchase panel:

1. breadcrumbs/collection subtle;
2. H1;
3. короткая конструктивная фраза;
4. цена «от» до полного выбора или точная цена после выбора;
5. selectors в логическом порядке;
6. lead time;
7. Add to cart;
8. Individual order secondary CTA;
9. delivery/payment short hints;
10. links to policy/details.

### 8.2. Variant selectors

Размер — pills/cards с мм или см в понятном формате.

Материал — cards со словом и, при наличии, фактурой.

Оттенок — swatch + текстовое название. Цвет нельзя сообщать только цветом: accessibility и разница экранов.

Отделка — текст/card, возможно tooltip «что это».

Unavailable state:

- disabled, но видимый вариант, если полезно понять ассортимент;
- короткая причина при необходимости;
- индивидуальный заказ может быть предложен, но не автоматически обещан.

### 8.3. Цена

До выбора:

`от 129 000 ₽`

После полного выбора:

`154 000 ₽`

Если цена изменилась из-за выбора, изменение должно быть визуально очевидно, но без агрессивной animation.

### 8.4. Галерея

Минимальный контент для сильной модели:

- hero/interior;
- 3/4 view;
- front/side;
- detail 45°;
- material close-up;
- функциональная деталь;
- размеры/diagram при наличии.

Lightbox keyboard-accessible.

### 8.5. Ниже purchase section

Порядок:

1. О модели;
2. Конструкция и детали;
3. Размеры;
4. Материалы и уход;
5. Производство;
6. Доставка и оплата;
7. FAQ только реальные;
8. Другие модели;
9. related article/material.

Не прятать все ключевые сведения в 8 аккордеонов только ради минимализма.

### 8.6. Mobile

- gallery первым экраном;
- name + price;
- selectors;
- основная CTA;
- sticky bottom bar после прохождения основной CTA: price + «В корзину»;
- bar учитывает cookie/consent overlay и safe area;
- lightbox и swatches usable пальцем.

## 9. Cart

Пользователь обязан видеть точную конфигурацию:

```text
Стол KHM 01
1800 × 900 мм
Дубовый шпон
Natural Oak
Масло Osmo
154 000 ₽
```

Нельзя показывать просто «Стол KHM 01 × 1».

Функции:

- change qty;
- delete;
- вернуться в карточку;
- clear notice при repricing;
- subtotal;
- доставка «рассчитывается/по правилам» без фиктивной суммы;
- CTA checkout.

Cart drawer может быть быстрым preview, но полноценная `/cart/` нужна для больших чеков и спокойной проверки конфигурации.

---

## 10. Checkout

Для дорогой мебели предпочтителен спокойный checkout на одной странице с визуальными секциями либо максимум 2–3 шага. Не создавать 6-step funnel.

Разделы:

1. Контактные данные;
2. Получатель/город/адрес, когда применимо;
3. способ доставки;
4. оплата;
5. состав заказа;
6. отдельное согласие ПДн и необходимые подтверждения;
7. CTA с конкретным действием («Оплатить 154 000 ₽» / «Оформить заказ» по утвержденной модели).

Обязательно:

- inline validation;
- сохранять введенные данные при ошибке;
- не требовать регистрации;
- ссылка на оферту/условия продажи до CTA;
- итоговый номер заказа после успешного оформления.

## 11. Личный кабинет

MVP:

- список заказов;
- detail order;
- понятный status timeline;
- конфигурация каждой позиции;
- платежный статус;
- контакты поддержки;
- профиль.

Не превращать в dashboard с графиками и «баллами», которых нет в бизнес-модели.

## 12. Для дизайнеров

Страница не должна быть обычной лид-формой под текстом.

Блоки:

1. hero «Производство предметной мебели для интерьерных проектов»;
2. что берем в работу;
3. реальные capabilities;
4. процесс взаимодействия;
5. материалы/детали;
6. портфолио индивидуальных проектов, если есть;
7. форма загрузки проекта;
8. FAQ по расчету/срокам без неподтвержденных обещаний.

Форма:

- имя;
- студия optional;
- телефон;
- email;
- город;
- описание;
- budget optional;
- desired date optional;
- multiple files;
- отдельное согласие ПДн.

---

## 13. О бренде

Не делать «стену текста».

Редакционная структура:

- короткий манифест;
- три поколения;
- производство сегодня;
- материалы;
- подход к дизайну;
- реальные фото;
- CTA коллекция.

Повествование должно оставаться фактическим. Если нет архивных фото деда/отца — не генерировать псевдоархив как документальное подтверждение.

---

## 14. Материалы и отделка

Каждый материал:

- что это;
- где используется;
- визуальные свойства;
- уход;
- ограничения;
- связанные модели.

Это одновременно UX, доверие и SEO.

Не публиковать неподтвержденные технические заявления вроде классов эмиссии, точной твердости или происхождения сырья без документов.

## 15. Blog/Journal

Визуально — журнал бренда, функционально — SEO-хаб.

Article template:

- breadcrumbs;
- H1;
- lead;
- author/editor/review date при наличии реального процесса;
- содержательное оглавление для длинных статей;
- качественные изображения;
- contextual product/category blocks;
- related reading.

Не вставлять агрессивный popup после каждого второго абзаца.

---

## 16. Motion

Allowed:

- gentle image reveal;
- opacity/translate 10–20px;
- gallery transitions;
- micro-interactions selectors;
- menu reveal.

Avoid:

- long scroll-jacking;
- parallax на каждом экране;
- тяжелые WebGL/3D в MVP;
- анимацию, задерживающую взаимодействие;
- autoplay video hero на мобильном без performance budget.

Уважать `prefers-reduced-motion`.

---

## 17. Accessibility

Минимальная планка — WCAG 2.2 AA как инженерная цель, даже если юридическая обязательность оценивается отдельно.

Требования:

- контраст;
- visible focus;
- keyboard navigation;
- semantic headings;
- labels;
- alt;
- aria только там, где HTML semantics недостаточно;
- swatch имеет текстовое имя;
- ошибки формы связаны с полями;
- modal traps focus/returns focus;
- no hover-only critical information;
- 200% zoom не ломает checkout.

---

## 18. Performance budget для дизайна

Дизайн не считается утвержденным, если он требует загрузить 12 полноразмерных JPEG на первом экране.

Цели при реальном mobile network profile:

- LCP ≤ 2.5 s как целевой Core Web Vitals порог;
- INP ≤ 200 ms;
- CLS ≤ 0.1;
- hero image имеет размеры/priority только если реально LCP;
- offscreen gallery lazy-loaded;
- WebP/AVIF где уместно;
- fonts subset/self-hosted;
- не более необходимых font weights;
- reserve aspect ratio для изображений.

---

## 19. Контент и фотография как часть дизайн-системы

Для премиального мебельного бренда фотография важнее декоративного UI.

Нужен единый art direction:

- neutral/warm color grading;
- реальные текстуры;
- detail macros;
- единый уровень горизонта/перспективы для catalog covers;
- сочетание cutout/neutral и interior shots;
- не смешивать случайные стили 3D-рендеров и фото.

Для каждого Product еще до публикации определить required media checklist.

## 21. Design QA Definition of Done

Страница готова к разработке только если:

- есть desktop + mobile;
- покрыты loading/empty/error states;
- реальные тексты хотя бы близкой длины;
- фото имеют ожидаемый aspect ratio;
- hover/focus/disabled selectors определены;
- sticky элементы не перекрываются;
- все CTA имеют понятное действие;
- компоненты переиспользуют библиотеку;
- нет фиктивных бизнес-обещаний;
- разработчик понимает поведение без догадок.
