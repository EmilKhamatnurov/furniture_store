# KHAMATNUROV MEBEL — Implementation Pack

Версия: 1.0 • 17 сентября 2026

## Назначение пакета

Этот комплект документов переводит исходное концептуальное ТЗ KHAMATNUROV MEBEL и текущую кодовую базу `furniture_store` в подробный план реализации промышленного интернет-магазина предметной мебели.

Документы рассчитаны одновременно на владельца проекта, дизайнера, SEO-специалиста, frontend/backend-разработчика и AI coding agent (ChatGPT / Claude Code / Copilot).

## Ключевое архитектурное решение

Базовая рекомендация: **не переписывать проект на WordPress/Bitrix**, а продолжать текущую реализацию как специализированную ecommerce-платформу KHAMATNUROV MEBEL на Next.js + PostgreSQL + Drizzle + Redis + BullMQ.

Причина: текущий репозиторий уже содержит работающие домены каталога, корзины, checkout, платежей, заказов, пользователей, админки, CMS, email-очередей и SEO-инфраструктуры. Перенос на CMS заставит повторно реализовать большую часть уже готовой бизнес-логики и ограничит будущий конфигуратор.

## Критическое действие до новой разработки

В `package.json` репозитория зафиксирован Next.js `^15.5.19`. 25 августа 2026 Next.js выпустил security release и рекомендовал обновить ветку 15.5 минимум до `15.5.24` из-за двух уязвимостей критической степени. Поэтому **P0-задача — обновить Next.js до последнего патча 15.5.x, прогнать сборку и тесты, и только затем начинать продуктовый рефакторинг**.

Переход на Next.js 16.3.x рекомендуется делать отдельной задачей после стабилизации тестового контура, а не одновременно с переделкой товарной модели.

## Как работать с документами

Для разработки используйте файлы 01–08 как «источник истины». Новая функциональность сначала фиксируется в `08_DECISION_LOG_OPEN_QUESTIONS.md`, затем переносится в соответствующий профильный документ и только после этого реализуется в коде.

Для AI coding agent перед началом каждой крупной задачи передавайте минимум:

- `01_MASTER_TZ_KHAMATNUROV_MEBEL.md`;
- профильный документ нужного этапа;
- `07_AI_DEVELOPER_RULES.md`;
- актуальный `SPEC.md` и `CLAUDE.md` из репозитория.

## Что считается запуском MVP

MVP в этом проекте — не «готовая главная». Он считается завершенным, когда пользователь может:

1. найти индексируемую категорию;
2. открыть модель мебели;
3. выбрать только допустимую комбинацию размера/материала/оттенка/отделки;
4. увидеть точную цену выбранного варианта;
5. положить именно этот вариант в корзину;
6. оформить заказ;
7. оплатить стандартный товар по утвержденной платежной схеме;
8. получить уведомление;
9. увидеть заказ в личном кабинете;
10. а менеджер — увидеть все параметры заказа и корректно провести его через производство и доставку.

Одновременно поисковая система должна получать серверный HTML, корректные canonical/robots/sitemap, структурированные данные товара и стабильные URL.
