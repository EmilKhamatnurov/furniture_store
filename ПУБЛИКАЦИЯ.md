# Инструкция по публикации сайта — KHAMATNUROV MEBEL

Пошаговый алгоритм: как выложить интернет-магазин в интернет, чтобы он работал.
Технические подробности CI/CD (автодеплой) — в файле `DEPLOY.md`.

> **Как устроен сайт.** Он состоит из нескольких «контейнеров» Docker, которые
> работают на одном сервере:
>
> | Контейнер | Назначение |
> |-----------|-----------|
> | `postgres` | база данных |
> | `redis` | кэш и очереди (письма) |
> | `migrate` | одноразово готовит БД перед запуском |
> | `app` | сам сайт (Next.js) |
> | `worker` | фоновая отправка писем |
> | `caddy` | принимает запросы из интернета и выдаёт HTTPS-сертификат |

> ⚠️ **Важно (152-ФЗ):** персональные данные клиентов по закону должны храниться
> в России → берите **российский** сервер (Selectel, Timeweb, Yandex Cloud).

---

## Что подготовить заранее

- [ ] **VPS (сервер)** в РФ: Ubuntu 22.04/24.04, минимум **2 CPU / 4 ГБ RAM**.
- [ ] **Домен** (например, `shop.example.ru`).
- [ ] **Аккаунт GitHub** (код будет храниться там).
- [ ] **ЮKassa** — `shop_id` и `secret_key` (приём онлайн-оплаты).
- [ ] **S3-хранилище (Selectel)** — ключи и бакет (для фотографий товаров).
- [ ] **Unisender Go** — API-ключ (отправка писем клиентам).

> Оплата, письма и фото начнут работать по мере заполнения соответствующих
> ключей. Технически сайт можно запустить и без них — но без приёма заказов.

---

## Этап 0. Подготовка кода (на своём компьютере)

**0.1. Убедиться, что проект собирается без ошибок:**
```bash
cd "Магазин мебели/Furniture store"
npm run build
```
Если есть ошибки — их нужно устранить до публикации.

**0.2. Залить код в Git** (если проект ещё не в репозитории):
```bash
git init
git add .
git commit -m "Первый коммит"
git branch -M main
git remote add origin git@github.com:ВАШ_ЛОГИН/khamatnurov-mebel.git
git push -u origin main
```
> Файлы с секретами (`.env`, `.env.local`, `.env.production`) в Git **не попадут** —
> они уже в `.gitignore`. Это правильно: секреты живут только на сервере.

---

## Этап 1. Настройка сервера (делается один раз)

**1.1. Подключиться к серверу:**
```bash
ssh root@IP_СЕРВЕРА
```

**1.2. Установить Docker:**
```bash
curl -fsSL https://get.docker.com | sh
```

**1.3. Настроить домен (DNS):**
В панели регистратора домена создайте **A-запись**:
`shop.example.ru → IP_СЕРВЕРА`. Подождите несколько минут.

**1.4. Скачать код на сервер:**
```bash
mkdir -p /opt/shop && cd /opt/shop
git clone git@github.com:ВАШ_ЛОГИН/khamatnurov-mebel.git .
```

---

## Этап 2. Конфигурация (заполнить секреты)

**2.1. Файл `.env`** (настройки для docker-compose):
```bash
cat > .env <<'EOF'
POSTGRES_PASSWORD=ПРИДУМАЙТЕ_СЛОЖНЫЙ_ПАРОЛЬ
DOMAIN=shop.example.ru
EOF
```

**2.2. Файл `.env.production`** (настройки приложения) — скопировать шаблон и заполнить:
```bash
cp .env.production.example .env.production
nano .env.production
```
Обязательно заполнить:
| Переменная | Что вписать |
|-----------|-------------|
| `NEXT_PUBLIC_APP_URL` | `https://shop.example.ru` |
| `APP_SECRET` | случайная строка — получить командой `openssl rand -hex 32` |
| `DATABASE_URL` | `postgresql://furniture_user:ТОТ_ЖЕ_ПАРОЛЬ@postgres:5432/furniture_shop` (пароль — как в `.env`) |
| `REDIS_URL` | `redis://redis:6379` |
| `S3_*` | данные хранилища Selectel |
| `YUKASSA_SHOP_ID`, `YUKASSA_SECRET_KEY`, `YUKASSA_WEBHOOK_SECRET` | из кабинета ЮKassa |
| `UNISENDER_API_KEY`, `EMAIL_FROM` | из кабинета Unisender |
| `ADMIN_EMAIL` | почта администратора |

**2.3. Пароль для входа в админку:**
```bash
docker compose run --rm migrate npm run admin:hash -- "ВАШ_ПАРОЛЬ_АДМИНА"
```
Скопируйте выведенную строку `ADMIN_PASSWORD_HASH=...` в `.env.production`.

---

## Этап 3. Запуск

**3.1. Собрать и запустить всё** (соберутся образы, применятся миграции БД,
поднимутся сервисы, Caddy сам выпустит SSL-сертификат):
```bash
docker compose --profile prod up -d --build
```
Через 1–2 минуты сайт откроется на `https://shop.example.ru`.

**3.2. Наполнить магазин данными** (категории, товары, зоны доставки):
```bash
docker compose run --rm migrate npm run db:seed
```

---

## Этап 4. После запуска

**4.1.** В кабинете **ЮKassa** указать адрес для уведомлений (webhook):
```
https://shop.example.ru/api/payments/yukassa/webhook
```

**4.2. Проверить:**
- сайт открывается по HTTPS;
- вход в админку: `https://shop.example.ru/admin/login`;
- оформить тестовый заказ.

**4.3.** Загрузить **реальные товары и фотографии** через админку и заменить
тексты юридических страниц (оферта, политика, реквизиты) на настоящие.

✅ **Готово — сайт опубликован.**

## Как выкладывать обновления

После первой публикации, когда что-то изменили в коде:

**Вариант А — вручную** (зайти на сервер):
```bash
cd /opt/shop
git pull
docker compose --profile prod up -d --build
```

**Вариант Б — автоматически (CI/CD)** — настраивается один раз по инструкции
в `DEPLOY.md`. После настройки достаточно на своём компьютере выполнить:
```bash
git add . && git commit -m "изменения" && git push
npm version patch && git push --follow-tags
```
Тег новой версии (`v0.1.1`) сам запустит публикацию на сервере.

## Полезные команды (эксплуатация)

```bash
# Статус контейнеров
docker compose --profile prod ps

# Логи (посмотреть ошибки)
docker compose --profile prod logs -f app
docker compose --profile prod logs -f caddy

# Перезапустить
docker compose --profile prod up -d --build

# Откатиться на предыдущую версию
git checkout v0.1.0 && docker compose --profile prod up -d --build

# Бэкап базы данных
docker exec furniture_postgres pg_dump -U furniture_user furniture_shop > backup_$(date +%F).sql
```

## Если что-то не работает

| Симптом | Что делать |
|---------|-----------|
| `502 Bad Gateway` | приложение ещё собирается или упало — `docker compose --profile prod logs app` |
| Нет HTTPS / сайт не открывается | проверьте A-запись домена и что порты 80/443 открыты |
| Сборка падает с нехваткой памяти | мало RAM — увеличьте тариф до ≥4 ГБ или добавьте swap |
| Не приходят письма | проверьте `UNISENDER_API_KEY` и логи: `docker compose --profile prod logs worker` |
| Оплата не подтверждается | проверьте webhook в ЮKassa и `YUKASSA_*` в `.env.production` |

## Минимум, чтобы сайт «просто заработал»

1. Сервер + домен.
2. Файлы `.env` и `.env.production`.
3. Команда `docker compose --profile prod up -d --build`.

Всё остальное (оплата, письма, фото) подключается заполнением ключей в
`.env.production` без изменения кода.
